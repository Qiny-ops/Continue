## 1. 登录页面刷新闪烁活动栏布局问题

### 问题描述
当用户在登录页面刷新浏览器时，会短暂闪烁显示活动栏布局，然后才显示正确的登录页面。

### 问题分析

#### 1.1 技术原因
- **Vue Router 初始化延迟**：浏览器刷新页面时，Vue Router 需要一定时间来初始化并解析当前路由路径
- **组件渲染顺序**：App.vue 组件在 Vue Router 完全初始化之前就开始渲染
- **条件渲染逻辑**：原始的 `isAuthRoute` 计算属性依赖于 `route.path`，在路由初始化前可能为空
- **路由判断依赖**：组件布局显示完全依赖于 Vue Router 的路由信息，而非直接从浏览器 URL 获取路径

#### 1.2 代码分析

**原始代码（有问题）**：
```vue
// App.vue 中的 isAuthRoute 计算属性
const isAuthRoute = computed(() => {
  const authRoutes = ['/login', '/register', '/forgot-password']
  return authRoutes.includes(route.path)
})
```

**问题分析**：
- 当 `route.path` 为空时，`isAuthRoute` 返回 `false`
- 导致条件渲染显示 `MainLayout` 组件，短暂显示活动栏布局
- Vue Router 初始化完成后，`route.path` 获得正确值，`isAuthRoute` 变为 `true`
- 组件重新渲染，显示正确的登录页面，造成闪烁

### 解决方案

#### 3.1 技术方案
- **直接获取初始路径**：在组件初始化时直接从 `window.location.pathname` 获取当前路径
- **优先使用初始路径**：在计算属性中优先使用初始路径，避免依赖 Vue Router 初始化
- **确保路径正确**：添加回退逻辑，确保在所有情况下都能获得正确的路径

#### 3.2 代码实现

**修改后的代码**：
```vue
// App.vue 中的修改
<script setup>
import { computed } from 'vue'
import { useRoute } from 'vue-router'
import MainLayout from '@/layout/AppLayout.vue'

// 路由实例
const route = useRoute()
// 初始路径，从浏览器URL直接获取
const initialPath = window.location.pathname

// 计算属性：判断是否为认证相关路由
const isAuthRoute = computed(() => {
  // 优先使用初始路径，避免路由初始化时的闪烁
  const currentPath = initialPath || route.path
  const authRoutes = ['/login', '/register', '/forgot-password']
  return authRoutes.some(authPath => currentPath === authPath)
})
</script>
```

#### 3.3 解决方案原理
- **避免初始化依赖**：直接使用浏览器的 `window.location.pathname`，无需等待 Vue Router 初始化
- **立即获得正确路径**：在组件首次渲染时就获得正确的路径信息
- **确保逻辑正确**：添加回退逻辑，确保在所有情况下都能正确判断路由类型

#### 3.4 最终优化方案（推荐）

上述方案存在一个问题：`initialPath` 是静态变量，在退出登录等路由切换场景下会导致判断失效。最终采用更可靠的方案：

**核心思路**：
1. 添加 `isReady` 状态，等待路由完全初始化后再渲染布局
2. 使用 `router.isReady()` 确保路由匹配完成
3. 改用 `route.meta.requiresAuth` 判断路由类型，更可靠

**最终代码**：
```vue
<template>
  <el-config-provider :locale="locale">
    <div id="app">
      <!-- 初始化加载状态 -->
      <div v-if="!isReady" class="app-loading">
        <div class="loading-spinner"></div>
      </div>

      <template v-else>
        <!-- 登录、注册等认证页面不使用布局 -->
        <router-view v-if="isAuthRoute" />

        <!-- 主应用使用布局 -->
        <MainLayout v-else>
          <router-view />
        </MainLayout>
      </template>
    </div>
  </el-config-provider>
</template>

<script setup>
import { computed, inject, ref, onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import MainLayout from '@/layout/AppLayout.vue'

const route = useRoute()
const router = useRouter()
const locale = inject('locale')

const isReady = ref(false)

const isAuthRoute = computed(() => {
  if (!route.matched.length) return true
  
  const meta = route.meta
  if (meta.requiresAuth === false) return true
  
  const standaloneRoutes = ['/demo/']
  return standaloneRoutes.some(prefix => route.path.startsWith(prefix))
})

onMounted(() => {
  if (router.isReady()) {
    isReady.value = true
  } else {
    router.isReady().then(() => {
      isReady.value = true
    })
  }
})
</script>

<style>
.app-loading {
  display: flex;
  align-items: center;
  justify-content: center;
  height: 100%;
  background: #f5f7fa;
}

.loading-spinner {
  width: 40px;
  height: 40px;
  border: 3px solid #e4e7ed;
  border-top-color: #409eff;
  border-radius: 50%;
  animation: spin 0.8s linear infinite;
}

@keyframes spin {
  to {
    transform: rotate(360deg);
  }
}
</style>
```

**方案优势**：
- **避免时序问题**：等待路由初始化完成后再渲染，彻底解决闪烁
- **响应式判断**：使用 `route.meta` 替代路径字符串匹配，更可靠
- **用户体验好**：初始化期间显示 loading 动画，避免白屏
- **兼容所有场景**：无论是刷新页面还是路由切换都能正确判断

## 2. 退出登录后登录页面显示布局问题

### 问题描述
当用户退出登录后，跳转到登录页面时会显示主应用布局（导航栏等），而不是独立的登录页面。

### 问题分析

#### 2.1 技术原因
- **initialPath 静态变量**：`window.location.pathname` 只在组件初始化时获取一次，之后不会变化
- **优先级错误**：计算属性中 `initialPath || route.path` 导致 `initialPath` 优先级高于响应式的 `route.path`
- **路由切换后判断失效**：退出登录时路由从其他页面切换到 `/login`，但 `isAuthRoute` 仍使用旧的 `initialPath` 值

#### 2.2 代码分析

**问题代码**：
```javascript
const route = useRoute()
const initialPath = window.location.pathname  // 只在初始化时获取一次

const isAuthRoute = computed(() => {
  const currentPath = initialPath || route.path  // initialPath 优先级错误
  const authRoutes = ['/login', '/register', '/forgot-password']
  return authRoutes.some(authPath => currentPath === authPath)
})
```

**问题流程**：
1. 用户在 `/projects` 页面 → `initialPath = '/projects'`（固定不变）
2. 点击退出登录 → `router.replace('/login')` → `route.path = '/login'`
3. 但 `isAuthRoute` 使用 `initialPath`（仍是 `/projects`），返回 `false`
4. 结果：登录页面被 `MainLayout` 包裹显示

### 解决方案

移除 `initialPath` 变量，直接使用响应式的 `route.path`：

```javascript
const route = useRoute()

const isAuthRoute = computed(() => {
  const currentPath = route.path  // 直接使用响应式的 route.path
  const authRoutes = ['/login', '/register', '/forgot-password']
  const standaloneRoutes = ['/demo/']
  return authRoutes.some(authPath => currentPath === authPath) ||
         standaloneRoutes.some(prefix => currentPath.startsWith(prefix))
})
```

### 解决方案原理
- **使用响应式数据**：`route.path` 是响应式的，会随路由变化实时更新
- **简化逻辑**：移除不必要的 `initialPath` 变量，避免静态值干扰
- **确保实时性**：每次路由变化时，计算属性都会重新计算，获得正确的判断结果

## 4. 用例列表编辑时刷新列表问题

### 问题描述
在用例列表中点击编辑按钮时，列表会被刷新，导致用户体验不佳。

### 问题分析

#### 4.1 技术原因
- **fallback 逻辑错误**：`handleEditCase` 函数中使用了 `||` fallback 逻辑
- **错误调用列表 API**：当 `getTestCase` 失败时，fallback 调用 `fetchTestCases({ id: row.id })`
- **列表数据被覆盖**：`fetchTestCases` 方法会覆盖整个 `testCases.value` 列表数据

#### 4.2 代码分析

**问题代码**：
```javascript
// ProjectTestCases.vue
const handleEditCase = async (row) => {
  isEditing.value = true
  editingCaseId.value = row.id

  try {
    // 问题：fallback 调用 fetchTestCases 会覆盖整个列表
    const detail = await testCases.getTestCase?.(row.id) || await testCases.fetchTestCases({ id: row.id })
    // ...
  }
}
```

**问题流程**：
1. 用户点击编辑按钮
2. 调用 `getTestCase(row.id)` 获取用例详情
3. 如果 `getTestCase` 返回空值或失败，fallback 调用 `fetchTestCases({ id: row.id })`
4. `fetchTestCases` 执行 `testCases.value = response.results || response || []`
5. 整个列表被替换成只包含单个用例的数据

### 解决方案

移除 fallback 逻辑，直接使用 `getTestCase` 获取单个用例详情：

```javascript
const handleEditCase = async (row) => {
  isEditing.value = true
  editingCaseId.value = row.id

  try {
    // 直接使用 getTestCase，不会影响列表数据
    const detail = await testCases.getTestCase(row.id)
    const caseDetail = Array.isArray(detail) ? detail[0] : detail
    // ...
  }
}
```

### 解决方案原理
- **单一职责**：`getTestCase` 只获取单个用例详情，不修改列表数据
- **避免副作用**：移除 fallback 逻辑，防止意外调用列表 API
- **保持列表稳定**：编辑操作不再影响列表数据
