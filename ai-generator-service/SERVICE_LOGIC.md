# AI Generator Service - 业务逻辑说明

## 一、服务定位

AI 模型推理微服务，提供两项核心业务能力：

| 业务能力 | 说明 | 应用场景 |
|----------|------|----------|
| 模型推理 | 调用 AI 模型处理用户请求 | 问答、文本生成、数据分析 |
| 测试用例生成 | 根据功能点自动生成测试用例 | 软件测试用例编写 |

---

## 二、推理业务逻辑

### 1. 单次推理

**业务场景：** 用户提出一个问题，AI 返回答案。

```
用户输入问题
    ↓
系统注入角色设定（system 消息）
    ↓
调用 AI 模型生成答案
    ↓
提取并解析 JSON（如果返回的是结构化数据）
    ↓
返回结果给用户
```

**业务规则：**

| 规则 | 说明 |
|------|------|
| 角色固定 | system 消息由服务端控制，用户无法修改 |
| 格式自动解析 | AI 返回内容自动提取 JSON，无需用户手动解析 |
| 失败重试 | 网络或模型故障时自动重试（最多 3 次） |

**输入输出：**

```
输入: messages[] - 用户对话消息列表
输出: {success, result, error} - 成功返回结果，失败返回错误信息
```

---

### 2. 流式推理

**业务场景：** 用户需要实时看到 AI 生成的内容（如长文本生成）。

```
用户输入问题
    ↓
系统注入角色设定
    ↓
调用 AI 模型（流式模式）
    ↓
逐字逐句实时推送给用户
    ↓
生成完成
```

**业务规则：**

| 规则 | 说明 |
|------|------|
| 实时输出 | 内容生成过程中实时推送，无需等待完成 |
| 原始返回 | 不做 JSON 提取，返回原始文本内容 |
| 适用场景 | 长文本生成、实时对话、内容创作 |

---

### 3. 批量推理

**业务场景：** 用户需要一次性处理多个问题。

#### 同步批量

```
用户提交多个问题
    ↓
依次处理每个问题
    ↓
全部处理完成后返回结果
```

**业务规则：**
- 必须等待所有问题处理完成
- 适合小批量（<10 个）
- 单个失败不影响其他问题

#### 异步批量

**业务场景：** 用户需要处理大量问题，不希望等待。

```
用户提交多个问题
    ↓
系统创建任务，立即返回任务 ID
    ↓
后台处理问题
    ↓
用户轮询查询进度和结果
```

**任务状态流转：**

```
PENDING（等待）→ PROCESSING（处理中）→ COMPLETED（完成）
                                    ↘ FAILED（失败）
```

**业务规则：**

| 规则 | 说明 |
|------|------|
| 即时响应 | 立即返回任务 ID，不阻塞用户 |
| 进度可查 | 用户可随时查询处理进度 |
| 结果保留 | 任务结果保留 1 小时后自动清理 |

---

## 三、测试用例生成业务逻辑

### 1. 业务场景

**用户需求：** 根据功能点描述，自动生成软件测试用例。

**输入信息：**

| 字段 | 说明 | 示例 |
|------|------|------|
| module | 模块名称 | 用户管理 |
| func_point | 功能点 | 用户登录 |
| related_detail | 关联需求（可选） | 支持手机号验证码登录 |
| test_directions | 测试方向列表 | 功能点测试、业务逻辑测试、其他测试 |

**输出结果：**

| 字段 | 说明 | 示例 |
|------|------|------|
| title | 用例标题 | 用户名密码登录-正常登录 |
| steps | 测试步骤 | 1. 打开登录页面\n2. 输入用户名密码\n3. 点击登录 |
| expected_result | 预期结果 | 登录成功，跳转首页 |
| priority | 优先级 | 高/中/低 |
| test_type | 测试类型 | 功能点测试 |

---

### 2. 核心业务流程

```
用户提供功能信息
    ↓
系统构建输入文本
    "模块：用户管理，功能点：用户登录
     关联需求：支持手机号登录"
    ↓
并行处理多个测试方向
    ├─→ 功能点测试 → 生成功能测试用例
    ├─→ 业务逻辑测试 → 生成业务测试用例
    └─→ 其他测试 → 生成异常/边界测试用例
    ↓
合并所有用例
    ↓
标准化用例格式
    ↓
返回完整用例列表
```

---

### 3. 测试方向业务含义

| 测试方向 | 测试目的 | 用例示例 |
|----------|----------|----------|
| 功能点测试 | 验证功能是否正常工作 | 正常登录、手机号登录 |
| 业务逻辑测试 | 验证业务规则是否正确 | 密码错误提示、账号锁定 |
| 其他测试 | 边界值、异常、安全等 | 空密码登录、SQL注入 |

**扩展测试方向：**

可在配置中添加新的测试方向：
- 性能测试：关注响应时间、并发能力
- 安全测试：关注漏洞、权限控制
- 兼容性测试：关注不同环境下的表现

---

### 4. 并行生成策略

**业务规则：** 多个测试方向**同时**调用模型生成，而非顺序处理。

**原因：** 
- 不同测试方向相互独立，无依赖关系
- 并行处理大幅缩短总耗时

**示例：**

```
顺序处理: 
  功能点测试(10秒) → 业务逻辑测试(10秒) → 其他测试(10秒) = 30秒

并行处理:
  功能点测试(10秒) ┐
  业务逻辑测试(10秒) ├─ 同时进行 = 10秒
  其他测试(10秒)   ┘
```

---

### 5. 错误容忍策略

**业务规则：** 部分测试方向生成失败不影响整体结果。

```
测试方向: [功能点测试, 业务逻辑测试, 其他测试]

场景1: 全部成功
  → 返回 3 个方向的合并用例

场景2: 功能点测试失败，其他成功
  → 返回业务逻辑测试 + 其他测试的用例
  → 记录警告日志

场景3: 全部失败
  → 返回错误 "未生成任何用例"
```

**业务意图：** 宁可返回部分结果，也不因单点失败导致整体不可用。

## 四、JSON 提取业务逻辑

### 1. 问题背景

AI 模型返回内容不稳定，可能包含：
- 思考过程标签
- Markdown 代码块
- 混合文本

### 2. 提取策略

```
AI 原始输出
    ↓
第一步：去除思考标签
    "<thought>分析中...</thought>[{用例数据}]"
    → "[{用例数据}]"
    ↓
第二步：定位 JSON 位置
    "结果如下：[{用例数据}]"
    → "[{用例数据}]"
    ↓
第三步：提取代码块
    "```json [{用例数据}] ```"
    → "[{用例数据}]"
    ↓
第四步：解析 JSON
    "[{用例数据}]" → Python 对象
    ↓
结构化数据返回给用户
```

**业务价值：** 用户无需关心 AI 返回格式，直接获取结构化数据。

## 五、任务管理业务逻辑

### 1. 任务生命周期

```
用户提交异步批量请求
    ↓
创建任务（PENDING 状态）
    ↓
开始处理（PROCESSING 状态）
    ↓
逐个处理请求，实时更新进度
    ↓
处理完成（COMPLETED 状态）
    或
处理失败（FAILED 状态）
    ↓
1小时后自动清理
```

### 2. 进度查询

用户可通过任务 ID 查询：

| 信息 | 说明 |
|------|------|
| status | 当前状态 |
| total | 总数量 |
| completed | 已完成数量 |
| results | 结果列表（完成后可用） |

**业务价值：** 用户可实时了解处理进度，决定是否继续等待。

---

## 六、重试机制

### 1. 触发场景

| 场景 | 说明 |
|------|------|
| 网络超时 | 网络不稳定导致请求失败 |
| 模型限流 | 模型服务请求过多触发限流 |
| 服务暂时不可用 | 模型服务短暂不可用 |

### 2. 重试策略

```
第一次调用失败
    ↓
等待 2 秒
    ↓
第二次调用失败
    ↓
等待 2 秒
    ↓
第三次调用失败
    ↓
返回错误信息
```

**业务价值：** 提高服务可用性，减少偶发故障影响用户体验。

---

## 七、业务规则汇总

| 业务场景 | 规则 | 目的 |
|----------|------|------|
| 单次推理 | system 消息服务端控制 | 确保输出格式稳定 |
| 单次推理 | 自动提取 JSON | 用户无需手动解析 |
| 流式推理 | 原始内容返回 | 实时输出，不做处理 |
| 批量推理 | 异步模式即时响应 | 避免用户长时间等待 |
| 用例生成 | 多方向并行 | 缩短生成耗时 |
| 用例生成 | 部分失败容忍 | 提高可用性 |
| 任务管理 | 结果保留1小时 | 平衡存储与可用性 |
| 所有场景 | 失败自动重试 | 提高成功率 |
