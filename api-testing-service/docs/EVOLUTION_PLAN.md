### Phase 2：用例自愈能力（第 3-4 月）

**目标**：接口变更时自动生成修复建议

#### 3.2.1 依赖分析引擎自愈

**问题背景**：依赖分析生成的 `run_list` 往往依赖 AI 理解，当文档不完整或理解偏差时，可能导致：
- 前置接口缺失
- 依赖顺序错误
- 变量提取路径错误
- 认证流程遗漏

**自愈闭环**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    依赖分析引擎自愈闭环                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   依赖分析生成 run_list                                              │
│       ↓                                                              │
│   执行测试用例                                                       │
│       ↓                                                              │
│   执行结果分析                                                       │
│       ↓                                                              │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │ 依赖问题识别                                                  │   │
│   │  ├─ 前置接口缺失                                              │   │
│   │  ├─ 依赖顺序错误                                              │   │
│   │  ├─ 变量提取失败                                              │   │
│   │  ├─ 参数填充错误                                              │   │
│   │  └─ 环境依赖遗漏                                              │   │
│   └─────────────────────────────────────────────────────────────┘   │
│       ↓                                                              │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │ 依赖知识沉淀                                                  │   │
│   │  ├─ 接口真实依赖关系                                          │   │
│   │  ├─ 正确的执行顺序                                            │   │
│   │  ├─ 有效的变量提取路径                                        │   │
│   │  └─ 环境必需条件                                              │   │
│   └─────────────────────────────────────────────────────────────┘   │
│       ↓                                                              │
│   下次依赖分析质量提升                                               │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

**问题类型与处理策略**：

| 问题类型 | 识别条件 | 处理策略 |
|----------|----------|----------|
| 前置接口缺失 | 401 但无登录接口 / 404 但无创建接口 | 自动补充前置接口 |
| 依赖顺序错误 | 使用变量但尚未提取 | 调整执行顺序 |
| 变量提取失败 | extract_vars 路径与响应不匹配 | 更正提取路径 |
| 参数填充错误 | 400 且参数校验失败 | 补充/修正参数 |
| 认证依赖遗漏 | 需认证但无 Token 传递 | 添加 Authorization header |

**run_list 质量评分**：

| 评分范围 | 等级 | 说明 |
|----------|------|------|
| 0.9+ | A | 依赖分析准确，可直接执行 |
| 0.8-0.9 | B | 有小问题，可自动修正 |
| 0.7-0.8 | C | 有中等问题，需人工审核 |
| 0.6-0.7 | D | 有严重问题，需重新分析 |
| <0.6 | F | 依赖分析失败 |

#### 3.3.1 基于 API 文档的高质量提示词生成

**核心理念**：API 接口文档蕴含最权威的接口定义，基于文档自动生成针对性提示词。

```
┌─────────────────────────────────────────────────────────────────────┐
│                    API 文档驱动的提示词生成                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   OpenAPI/Swagger 文档                                               │
│       ↓                                                              │
│   文档解析与结构化                                                    │
│       ├─ 提取接口定义                                                │
│       ├─ 提取参数规范（min/max/pattern/enum）                        │
│       ├─ 提取响应定义                                                │
│       └─ 提取业务描述                                                │
│       ↓                                                              │
│   提示词模板生成                                                      │
│       ├─ 接口特定的测试要求                                          │
│       ├─ 参数特定的边界定义                                          │
│       ├─ 响应特定的断言规则                                          │
│       └─ 业务特定的场景覆盖                                          │
│       ↓                                                              │
│   高质量提示词 ──→ 测试用例生成                                       │
│       ↓                                                              │
│   用例质量提升 (覆盖度 +36%, 可执行性 +27%)                          │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

**提示词组成部分**：

| 部分 | 内容来源 | 作用 |
|------|----------|------|
| 接口概览 | API 规范 summary/description | 明确接口用途 |
| 参数约束 | schema 定义 min/max/pattern | 生成边界测试 |
| 响应断言 | responses 定义字段 | 明确断言规则 |
| 边界场景 | 自动从约束生成 | 覆盖边界条件 |
| 测试要求 | 统一格式规范 | 保证输出质量 |

**提示词质量评估**：

| 维度 | 权重 | 检查内容 |
|------|------|----------|
| API 覆盖度 | 25% | 是否覆盖所有接口信息 |
| 参数精确度 | 25% | 参数约束是否精确 |
| 边界覆盖度 | 20% | 边界场景是否完整 |
| 断言清晰度 | 15% | 断言规则是否清晰 |
| 格式完整性 | 15% | 格式要求是否完整 |
