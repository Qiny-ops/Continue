## 一、项目架构与设计

### 1.1 系统架构

**Q1: 请介绍本项目的整体架构设计**

**参考答案：**

首先，本项目采用前后端分离的架构设计。后端使用Django REST Framework提供RESTful API，前端使用Vue3构建单页应用（SPA）。这种架构的优势在于：
- **职责分离**：前后端独立开发、独立部署
- **技术解耦**：前后端可以独立升级技术栈
- **扩展性好**：API可以被多个客户端复用（Web、移动端）

其次，本项目的具体技术选型如下：

| 层级 | 技术选型 | 选择原因 |
|------|----------|----------|
| 后端框架 | Django + DRF | 快速开发、ORM强大、认证完善 |
| 前端框架 | Vue3 + Element Plus | 响应式、组件化、生态丰富 |
| 数据库 | SQLite → PostgreSQL | 开发便捷、生产稳定 |
| 认证方案 | JWT Token | 无状态、跨域友好 |

最后，我设计的数据流如下：
```
用户操作 → Vue组件 → Axios请求 → Django API → ORM → 数据库
                ↓
         JWT Token认证
```

**深度思考：** 在架构设计时，我考虑过使用GraphQL替代REST API。但考虑到团队熟悉度和项目规模，最终选择REST API。如果项目后期需要更灵活的数据查询，可以引入GraphQL作为补充。

**Q2: 为什么选择Django REST Framework而不是Flask？**

**参考答案：**

首先，从开发效率角度考虑，DRF提供了开箱即用的功能：
- **自动生成API文档**：通过`drf-yasg`自动生成Swagger文档
- **内置认证系统**：JWT、Session、Token等多种认证方式
- **序列化器**：自动处理数据验证和转换
- **分页、过滤、排序**：内置支持，无需重复造轮子

其次，从项目需求角度考虑，本项目需要：
- 用户认证和权限管理
- 复杂的数据模型关联（项目-用例-步骤）
- RESTful API快速开发
- 这些需求DRF都能快速满足

最后，对比Flask的优劣势：

| 对比项 | Django REST Framework | Flask |
|--------|----------------------|-------|
| 开发速度 | 快（内置功能多） | 慢（需要自己组装） |
| 学习曲线 | 中等 | 低 |
| 灵活性 | 中等 | 高 |
| 适用场景 | 中大型项目 | 小型项目/微服务 |

**实际经验：** 在本项目中，使用DRF后，我只需要定义Serializer和ViewSet，API就自动生成了。如果用Flask，需要手动处理认证、验证、序列化等，开发时间至少增加50%。

**Q4: 如何处理N+1查询问题？**

**参考答案：**

首先，我会解释什么是N+1查询问题：
```python
# 问题代码 - N+1查询
projects = Project.objects.all()
for project in projects:
    print(project.created_by.username)  # 每次循环都查询一次用户表
# 结果：1次查询项目 + N次查询用户 = N+1次查询
```

其次，我会使用`select_related`和`prefetch_related`优化：

```python
# 方案1：select_related - 用于外键关系
projects = Project.objects.select_related('created_by').all()
for project in projects:
    print(project.created_by.username)  # 不会额外查询
# 结果：1次JOIN查询

# 方案2：prefetch_related - 用于多对多关系
projects = Project.objects.prefetch_related('members').all()
for project in projects:
    for member in project.members.all():
        print(member.username)
# 结果：2次查询（项目表 + 成员表）
```

最后，我会在Django Debug Toolbar中监控查询：

```python
# settings.py
INSTALLED_APPS += ['debug_toolbar']

# 使用后发现的优化点
# 1. 项目列表页：添加select_related('created_by')
# 2. 用例列表页：添加select_related('project', 'created_by')
# 3. 步骤列表页：添加select_related('testcase')
```

**实际效果：**
- 优化前：项目列表页查询次数 = 1 + N（用户数）
- 优化后：项目列表页查询次数 = 1（JOIN查询）
- 性能提升：约80%

class LoginView(APIView):

class RefreshTokenView(APIView):

                'code': 200,
                'data': {
                    'token': new_access_token

**Q7: 如何实现权限控制？**

**参考答案：**

首先，我会定义自定义权限类：

```python
# permissions.py
class IsOwnerOrReadOnly(permissions.BasePermission):
    """
    只允许创建者编辑，其他用户只读
    """
    def has_object_permission(self, request, view, obj):
        if request.method in permissions.SAFE_METHODS:
            return True
        
        return obj.created_by == request.user

class IsProjectMember(permissions.BasePermission):
    """
    只允许项目成员访问
    """
    def has_object_permission(self, request, view, obj):
        return request.user in obj.members.all()
```

其次，我会在视图中使用权限：

```python
# views.py
class ProjectViewSet(viewsets.ModelViewSet):
    permission_classes = [IsAuthenticated, IsOwnerOrReadOnly]
    
    def get_queryset(self):
        # 用户只能看到自己创建的项目或参与的项目
        return Project.objects.filter(
            models.Q(created_by=self.request.user) |
            models.Q(members=self.request.user)
        ).distinct()
```

最后，我会在Serializer中验证权限：

```python
# serializers.py
class ProjectSerializer(serializers.ModelSerializer):
    def update(self, instance, validated_data):
        # 验证是否有编辑权限
        if instance.created_by != self.context['request'].user:
            raise serializers.ValidationError("您没有权限编辑此项目")
        
        return super().update(instance, validated_data)
```

**实际经验：** 在本项目中，我发现一个安全问题：未授权用户可以访问所有API。解决方案是为所有需要认证的视图添加`IsAuthenticated`权限类。

**Q9: 如何处理大量数据导出？**

**参考答案：**

首先，我会分析问题：
- 一次性加载所有数据会导致内存溢出
- 同步处理会阻塞请求，用户体验差

其次，我会实现流式导出：

```python
# views.py
from django.http import StreamingHttpResponse
import csv

class ExportProjectView(APIView):
    permission_classes = [IsAuthenticated]
    
    def get(self, request, project_id):
        project = Project.objects.get(id=project_id)
        testcases = TestCase.objects.filter(project=project)
        
        def generate():
            # 生成CSV头部
            yield ['ID', '标题', '优先级', '状态', '创建时间']
            
            # 分批查询，避免内存溢出
            for testcase in testcases.iterator():
                yield [
                    testcase.id,
                    testcase.title,
                    testcase.priority,
                    testcase.status,
                    testcase.created_at.strftime('%Y-%m-%d %H:%M:%S')
                ]
        
        response = StreamingHttpResponse(
            csv.writer(response).writerows(generate()),
            content_type='text/csv'
        )
        response['Content-Disposition'] = f'attachment; filename="project_{project_id}.csv"'
        
        return response
```

**Q11: 如何封装Axios请求？**

**参考答案：**

首先，我会创建Axios实例：

```javascript
// utils/request.js
import axios from 'axios'
import { ElMessage } from 'element-plus'
import router from '@/router'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
})

// 请求拦截器
request.interceptors.request.use(
  config => {
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  error => {
    return Promise.reject(error)
  }
)

// 响应拦截器
request.interceptors.response.use(
  response => {
    const res = response.data
    
    if (res.code !== 200) {
      ElMessage.error(res.message || '请求失败')
      
      // Token过期，跳转登录
      if (res.code === 401) {
        localStorage.removeItem('token')
        router.push('/login')
      }
      
      return Promise.reject(new Error(res.message || '请求失败'))
    }
    
    return res
  },
  error => {
    ElMessage.error(error.message || '网络错误')
    return Promise.reject(error)
  }
)

export default request
```

# validators.py
from django.core.exceptions import ValidationError
import re

def validate_password_strength(password):
    """
    密码强度验证：
    - 至少8个字符
    - 包含大写字母
    - 包含小写字母
    - 包含数字
    - 包含特殊字符
    """
    if len(password) < 8:
        raise ValidationError('密码至少8个字符')
    
    if not re.search(r'[A-Z]', password):
        raise ValidationError('密码必须包含大写字母')
    
    if not re.search(r'[a-z]', password):
        raise ValidationError('密码必须包含小写字母')
    
    if not re.search(r'\d', password):
        raise ValidationError('密码必须包含数字')
    
    if not re.search(r'[!@#$%^&*(),.?":{}|<>]', password):
        raise ValidationError('密码必须包含特殊字符')

# models.py
class User(AbstractUser):
    password = models.CharField(
        max_length=128,
        validators=[validate_password_strength]
    )

## 附：面试技巧

### 回答结构化

使用"首先...其次...最后..."的结构，让回答更有条理：

**示例：**
> 首先，我会分析需求...
> 其次，我会设计方案...
> 最后，我会实现并测试...

### 结合项目

用实际项目经验支撑回答，增加可信度：

**示例：**
> 在本项目中，我遇到了N+1查询问题，通过使用select_related优化，查询次数从N+1降到1，性能提升80%。

### 展示深度

不仅说怎么做，还要说为什么：

**示例：**
> 我选择Django REST Framework而不是Flask，原因是DRF内置了认证、序列化、分页等功能，开发效率提升50%以上。

### 承认不足

遇到不会的问题，诚实回答并展示学习能力：

**示例：**
> 这个问题我目前不太了解，但根据我的理解，应该是...我会在面试后深入学习这个知识点。

### 提问互动

面试结束前，准备有质量的问题：

**示例问题：**
1. 贵公司的技术栈是什么？有哪些技术挑战？
2. 开发团队如何进行代码审查和技术分享？
3. 贵公司对新技术引入的态度和流程是怎样的？
4. 开发人员的职业发展路径是怎样的？
5. 贵公司目前面临的最大技术挑战是什么？
