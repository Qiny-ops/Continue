# 测试用例管理平台 - 业务逻辑说明

## 一、平台定位

测试用例管理系统（TCMS），面向测试团队的专业化测试用例管理平台，解决传统 Excel/Word 管理方式的痛点：
- 协作困难、版本混乱、复用性差
- 统计困难、关联性弱、检索效率低

---

## 二、核心业务模块

| 模块 | 核心业务 | 业务价值 |
|------|----------|----------|
| 用户管理 | 用户注册、登录、权限控制 | 平台访问控制 |
| 项目管理 | 项目创建、成员管理、配置 | 测试项目组织 |
| 用例库管理 | 用例库、版本、模块管理 | 用例结构化存储 |
| 用例管理 | 用例编写、导入导出、复制 | 测试内容管理 |
| 评审管理 | 评审流程、评审记录 | 用例质量把控 |
| 执行管理 | 执行记录、结果统计 | 测试执行跟踪 |
| 统计报表 | 项目统计、用例统计、执行统计 | 数据可视化 |

## 三、用户管理业务逻辑

### 1. 用户注册流程

```
用户填写注册信息
    ↓
前端校验：格式、长度、密码强度
    ↓
后端校验：用户名唯一、邮箱唯一
    ↓
密码加密存储（PBKDF2）
    ↓
创建用户记录（状态 active）
    ↓
分配默认角色（guest）
    ↓
返回成功
```

**业务规则：**

| 规则 | 说明 |
|------|------|
| 用户名唯一 | 全局唯一，不区分大小写 |
| 邮箱唯一 | 全局唯一，不区分大小写 |
| 密码强度 | 至少8位，含大小写字母和数字 |
| 默认角色 | 新用户默认为 guest（访客） |
| 默认状态 | 新用户默认为 active |

### 2. 用户登录流程

```
用户输入用户名/邮箱 + 密码
    ↓
验证用户凭证
    ↓
检查用户是否存在
    ↓ [不存在]
返回"用户名或密码错误"（不提示具体错误）
    ↓ [存在]
检查密码是否正确
    ↓ [不正确]
返回"用户名或密码错误"
    ↓ [正确]
检查用户状态是否为 active
    ↓ [非 active]
返回"账号已被禁用"
    ↓ [active]
生成 JWT Token（有效期24小时）
    ↓
更新最后登录时间和IP
    ↓
返回用户信息 + Token
```

**安全规则：**
- 密码错误不提示具体是用户名还是密码错误
- 连续失败5次可锁定账户30分钟（可选）
- Token 有效期24小时

### 3. 密码重置流程

```
用户点击"忘记密码"
    ↓
输入注册邮箱
    ↓
验证邮箱是否已注册
    ↓ [未注册]
返回"邮箱未注册"
    ↓ [已注册]
生成重置令牌（32位随机字符串）
    ↓
设置过期时间（24小时）
    ↓
发送重置邮件
    ↓
用户点击邮件链接
    ↓
验证令牌有效性
    ↓ [无效/过期]
返回错误
    ↓ [有效]
用户设置新密码
    ↓
更新密码，清除令牌
    ↓
跳转登录页
```

## 四、项目管理业务逻辑

### 1. 项目数据结构

| 属性 | 说明 | 业务含义 |
|------|------|----------|
| name | 项目名称 | 显示名称，可重复 |
| code | 项目标识 | 全局唯一标识符 |
| type | 项目类型 | web/mobile/api/performance/security |
| status | 项目状态 | active/completed/pending/archived |
| owner | 项目负责人 | 项目创建者 |

### 2. 项目创建流程

```
用户填写项目信息
    ↓
校验项目标识唯一性
    ↓ [不唯一]
返回"项目标识已存在"
    ↓ [唯一]
创建项目记录
    ↓
创建者自动成为项目管理员
    ↓
自动创建默认用例库
    ↓
自动创建默认版本
    ↓
返回项目信息
```

**自动化规则：**
- 创建者自动成为项目管理员
- 自动创建默认用例库和默认版本
- 无需用户手动创建基础结构

### 3. 项目成员管理

**添加成员流程：**

```
项目管理员选择用户
    ↓
指定项目角色（admin/developer/tester/viewer）
    ↓
检查用户是否已在项目中
    ↓ [已存在]
返回"用户已是项目成员"
    ↓ [不存在]
创建成员关联记录
    ↓
用户获得项目权限
```

**成员角色权限：**

| 角色 | 权限范围 |
|------|----------|
| admin | 项目管理、成员管理、用例管理、执行管理、报表 |
| developer | 用例查看、缺陷查看、报表查看 |
| tester | 用例管理、用例执行、缺陷提交、报表查看 |
| viewer | 用例查看、报表查看（只读） |

**业务规则：**
- 同一用户在一个项目中只能有一个角色
- 不能移除项目创建者（owner）

## 五、用例库管理业务逻辑

### 1. 用例组织结构

```
项目（Project）
    ↓
用例库（Repository）    ← 一个项目可有多个用例库
    ↓
版本（Version）         ← 一个用例库可有多个版本
    ↓
模块（Module）          ← 支持多级树形结构
    ↓
测试用例（TestCase）    ← 具体测试内容
    ↓
测试步骤（TestStep）    ← 用例执行步骤
```

### 2. 用例库管理

**业务规则：**

| 规则 | 说明 |
|------|------|
| 默认用例库 | 每个项目至少有一个默认用例库 |
| 删除级联 | 删除用例库会级联删除所有版本、模块、用例 |

### 3. 版本管理

**版本状态：**

| 状态 | 业务含义 |
|------|----------|
| active | 活跃版本，可编辑用例 |
| archived | 归档版本，用例只读不可编辑 |

**业务规则：**
- 每个用例库至少有一个默认版本
- 设置默认版本时自动取消其他版本的默认状态
- 归档版本后用例不可编辑（防止误改历史数据）

### 4. 模块管理

**树形结构：**

```
用户模块（根节点）
├── 登录功能（一级）
│   ├── 正常登录（二级）
│   └── 异常登录（二级）
├── 注册功能（一级）
│   ├── 手机注册（二级）
│   └── 邮箱注册（二级）
└── 个人中心（一级）
```

**业务规则：**
- 支持多级嵌套（无层级限制）
- 模块名称在同一层级内不能重复
- 删除模块时可选择：
  - 同时删除模块下的用例
  - 将用例移动到父模块或指定模块

## 六、用例管理业务逻辑

### 1. 测试用例数据结构

| 属性 | 说明 | 业务含义 |
|------|------|----------|
| title | 用例标题 | 测试场景描述 |
| module | 所属模块 | 分类归属 |
| version | 所属版本 | 版本归属 |
| priority | 优先级 | P0/P1/P2/P3 |
| precondition | 前置条件 | 执行前必须满足的条件 |
| steps | 测试步骤 | 操作步骤列表 |
| expected_result | 预期结果 | 每步的预期输出 |
| automation_status | 自动化状态 | 未分析/未自动化/已自动化 |

### 2. 优先级业务含义

| 优先级 | 含义 | 使用场景 |
|--------|------|----------|
| P0 | 最高 | 核心功能、冒烟测试、阻塞问题 |
| P1 | 高 | 重要功能、主要业务流程 |
| P2 | 中 | 一般功能、次要流程 |
| P3 | 低 | 边界场景、异常处理、UI细节 |

### 3. 用例创建流程

```
选择所属版本和模块
    ↓
填写基本信息（标题、优先级、前置条件）
    ↓
添加测试步骤（步骤描述 + 预期结果）
    ↓
[可选] 添加标签、关联需求、设置自动化状态
    ↓
保存用例
    ↓
[可选] 发起评审
```

### 4. 用例编辑规则

| 规则 | 说明 |
|------|------|
| 创建者可编辑 | 用例创建者可编辑自己的用例 |
| 管理员可编辑 | 项目管理员可编辑所有用例 |
| 归档版本不可编辑 | 归档版本的用例锁定，防止修改历史 |
| 自动记录变更 | 编辑后自动更新 updated_at 和 updated_by |

### 5. 用例复制

```
选择要复制的用例
    ↓
创建新用例记录
    ↓
复制所有测试步骤
    ↓
标题自动添加"(复制)"后缀
    ↓
新用例为独立状态（与原用例无关联）
```

### 6. 批量操作

| 操作 | 业务场景 |
|------|----------|
| 批量复制 | 复制一批用例到其他模块/版本 |
| 批量移动 | 将用例迁移到新模块 |
| 批量删除 | 删除废弃用例（需二次确认） |
| 批量修改优先级 | 统一调整用例优先级 |
| 批量修改标签 | 为用例统一添加标签 |

### 7. 用例导入导出

**Excel 导入流程：**

```
下载导入模板
    ↓
按模板格式填写用例数据
    ↓
上传 Excel 文件
    ↓
系统解析文件
    ↓
数据校验（必填项、格式、模块路径）
    ↓ [校验失败]
返回错误报告（列出具体错误行）
    ↓ [校验通过]
预览导入数据
    ↓
用户确认导入
    ↓
批量创建用例（自动创建模块）
    ↓
返回导入结果（成功数、失败数）
```

**导入规则：**
- 模块路径不存在时自动创建
- 支持最多20个测试步骤
- 多个标签用逗号分隔

**Excel 导出选项：**

| 选项 | 说明 |
|------|------|
| 导出范围 | 全部用例 / 选定用例 / 按模块导出 |
| 导出格式 | Excel (.xlsx) / CSV |
| 包含内容 | 基本信息 + 步骤 / 仅基本信息 |

## 七、用例评审业务逻辑

### 1. 评审流程

```
用例创建者提交评审
    ↓
评审人收到通知
    ↓
评审人查看用例内容
    ↓
评审人填写评审意见
    ↓
评审人选择评审结果
    ├── 通过 → 用例状态更新为已评审
    ├── 拒绝 → 返回修改意见给创建者
    └── 待定 → 等待更多信息
    ↓
通知相关人员
    ↓
[拒绝后] 创建者修改用例
    ↓
[拒绝后] 创建者重新提交评审
```

### 2. 评审业务规则

| 规则 | 说明 |
|------|------|
| 多次评审 | 每个用例可以有多次评审记录 |
| 最新状态决定 | 最新评审状态决定用例当前评审状态 |
| 修改后重评 | 拒绝后创建者可修改并重新提交 |
| 不能自评 | 评审人不能评审自己创建的用例 |

## 八、用例执行业务逻辑

### 1. 执行结果定义

| 结果 | 含义 | 后续动作 |
|------|------|----------|
| pass | 通过 | 无需后续处理 |
| fail | 失败 | 需提交缺陷报告 |
| block | 阻塞 | 记录阻塞原因，等待解决后继续 |
| skip | 跳过 | 记录跳过原因（如环境不支持） |

### 2. 执行流程

```
选择要执行的用例
    ↓
查看用例详情（前置条件、步骤、预期结果）
    ↓
按步骤逐一执行测试
    ↓
每步记录实际结果与预期是否一致
    ↓
选择整体执行结果
    ├── 通过 → 记录实际结果
    ├── 失败 → 记录缺陷信息
    ├── 阻塞 → 记录阻塞原因
    └── 跳过 → 记录跳过原因
    ↓
保存执行记录
    ↓
更新用例执行统计（通过率）
```

### 3. 执行记录数据

| 属性 | 说明 |
|------|------|
| test_case | 关联的测试用例 |
| executed_by | 执行人 |
| result | 执行结果 |
| actual_result | 实际结果描述 |
| remark | 执行备注 |
| executed_at | 执行时间 |

## 十、权限控制业务逻辑

### 1. 双重角色体系

**系统角色（全局）：**

| 角色 | 权限范围 |
|------|----------|
| super_admin | 系统最高权限，可管理所有用户和项目 |
| admin | 系统管理员，可管理用户和项目 |
| test_manager | 测试经理，可创建项目、管理团队 |
| test_engineer | 测试工程师，可编写和执行用例 |
| developer | 开发工程师，可查看用例 |
| product_manager | 产品经理，可查看和验收 |
| guest | 访客，只读权限 |

**项目角色（项目内）：**

| 角色 | 项目内权限 |
|------|------------|
| admin | 项目所有权限 |
| developer | 用例查看、报表查看 |
| tester | 用例管理、用例执行 |
| viewer | 只读权限 |

### 2. 权限校验逻辑

```
用户访问资源
    ↓
检查用户是否登录
    ↓ [未登录]
返回401，跳转登录页
    ↓ [已登录]
检查用户系统角色
    ↓
检查用户项目角色
    ↓
判断是否有权限
    ↓ [有权限]
允许访问
    ↓ [无权限]
返回403，提示无权限
```

## 十二、业务规则汇总

### 唯一性约束

| 数据 | 唯一性规则 |
|------|------------|
| 用户名 | 全局唯一 |
| 邮箱 | 全局唯一 |
| 项目标识 | 全局唯一 |
| 模块名称 | 同层级唯一 |
| 用例标题 | 同模块内唯一 |

### 默认值规则

| 场景 | 默认值 |
|------|--------|
| 新用户角色 | guest |
| 新用户状态 | active |
| 新项目状态 | active |
| 新用例库 | is_default=true |
| 新版本 | is_default=true |
| 新用例优先级 | p2 |
| 新用例自动化状态 | not_analyzed |

### 删除规则

| 数据 | 删除影响 |
|------|----------|
| 用户 | 关联的项目成员记录保留 |
| 项目 | 级联删除用例库、版本、模块、用例 |
| 用例库 | 级联删除版本、模块、用例 |
| 版本 | 级联删除模块、用例 |
| 模块 | 可选择级联删除或移动用例 |
| 用例 | 级联删除步骤、评审、执行记录 |

### 编辑锁定规则

| 场景 | 锁定条件 |
|------|----------|
| 归档版本用例 | version.status=archived |
| 非创建者用例 | 需项目管理员权限 |
| 项目创建者 | 不能被移除成员 |
