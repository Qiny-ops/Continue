2. 功能阻断问题 (Breaking)

Breaking
2.1 前端 requirement 数据契约断裂
TestCase.requirement: CharField → ForeignKey
根因：TestCase.requirement 从 CharField(max_length=500) 改为 ForeignKey(Requirement, null=True)。
DRF ModelSerializer 自动生成 PrimaryKeyRelatedField，只接受整数 ID，不再接受文本字符串。
前端受影响位置（5 处）：
# 1. TestCaseDialog.vue:211 — 创建/编辑测试用例 <el-input v-model="localForm.requirement" placeholder="请输入关联需求" /> → 用户输入文本 "REQ-LOGIN-001" → 后端期望整数 ID → 400 错误 # 2. ProjectTestCases.vue:344 — 评审编辑 <el-input v-model="reviewEditForm.requirement" placeholder="请输入关联需求" /> → 同问题，评审编辑提交时 requirement 为文本 → 400 # 3. ProjectTestCases.vue:547/629 — 数据初始化和提交 requirement: caseDetail.requirement || '' # 从详情读取 FK ID requirement: form.requirement # 提交时传文本 → 400 # 4. export.js:26/70 — CSV 导出 '关联需求': tc.requirement || '' # 现在显示整数 ID 而非 "REQ-LOGIN-001" # 5. useTestCaseReview.js:114/143 — 评审组合式函数 reviewEditForm.requirement = c.requirement || '' # 整数 ID → 显示为数字
影响：所有测试用例的"关联需求"字段在创建/编辑/导出/评审中均不可用。
用户无法通过前端输入新的关联需求；查看已有数据时显示数字 ID 而非可读文本。
Breaking
2.2 TestCase 序列化器输出契约变更
TestCaseDetailSerializer / TestCaseListSerializer
序列化器字段列表包含 'requirement'。ModelSerializer 对 FK 默认返回主键值（整数）。
前端代码（TestCaseDialog.vue、ProjectTestCases.vue、export.js）期望 requirement 为字符串。
影响：GET 请求返回的 requirement 从 "REQ-LOGIN-001" 变为 1/2/3...（FK ID）。
前端列表页面、详情弹窗、CSV 导出全部显示错误数据。

3. 数据风险

Data Risk
3.1 历史需求数据全部丢失
TestCase.requirement 迁移无数据转换脚本
Django CharField→ForeignKey 迁移时，Django 会先删除旧列再创建新列。
旧 requirement 列的文本值（如 "REQ-LOGIN-001"）在迁移执行时直接丢弃，新 requirement_id 列全部为 NULL。
所有历史测试用例的关联需求信息永久丢失。
影响：生产数据库中所有现有测试用例的 requirement 字段变为 NULL。
需要数据迁移脚本：创建对应的 Requirement 记录，然后建立 FK 关联。
Data Risk
3.2 User.email unique 约束可能导致迁移失败
users/migrations/0001_initial.py（squashed 后）
新增 unique=True 约束。如果数据库中已有重复邮箱的用户记录，migrate 会失败。
需要先运行数据清洗脚本去除重复邮箱。
影响：有重复邮箱的数据库无法完成迁移，部署阻塞。
Dev Tool
3.3 seed_test_data.py 不可用
management/commands/seed_test_data.py
所有 seed 数据（12 条用例）使用 'requirement': 'REQ-LOGIN-001' 文本字符串。
ORM 的 TestCase.objects.create(**data) 中 requirement 期望 FK 对象，传入字符串抛出 ValueError。
影响：开发环境初始化命令失效。需先创建 Requirement 对象再关联。

5. 修复建议

P0 — 立即修复（功能阻断）

修复 1：TestCaseCreateUpdateSerializer requirement 字段兼容化
将自动生成的 PrimaryKeyRelatedField 改为自定义字段，支持：
  • 接受整数 FK ID（正常关联）
  • 接受字符串 → 查找 Requirement.objects.filter(title=value).first() → 取 ID（向后兼容旧前端）
  • 序列化输出时返回 Requirement.title 而非 ID（前端显示友好）
修复 2：TestCaseDetailSerializer / TestCaseListSerializer requirement 输出改造
将 requirement 从默认 FK 字段改为 SerializerMethodField，返回 {'id': obj.requirement_id, 'title': obj.requirement.title if obj.requirement else ''}。
前端可继续用 tc.requirement || '' 读取。
修复 3：admin.py search_fields
已修复：'requirement' → 'requirement__title' ✅

P1 — 数据恢复（数据风险）

修复 4：数据迁移脚本
创建 RunPython 迁移：遍历旧 requirement 文本值 → 提取需求编号（如 REQ-LOGIN-001） → 创建 Requirement 记录 → 建立 FK 关联。
仅适用于从旧数据库迁移场景；新部署跳过。
修复 5：seed_test_data.py 更新
先创建 Requirement 对象列表，再用 FK 关联到 TestCase。
