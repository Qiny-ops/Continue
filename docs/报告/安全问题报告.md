## 问题1: 弱密码被接受

### 问题描述
系统允许用户注册时使用弱密码（如 `123456`, `password`, `qwerty` 等），没有密码强度验证。

### 问题位置
- 文件: `apps/users/views.py`
- 函数: `register_view()` (第260-315行)
- 代码位置: 第271行只检查密码是否为空

### 问题代码
```python
# 验证参数
if not all([username, password, email]):
    return JsonResponse({'code': 400, 'message': '用户名、密码和邮箱不能为空'})
# 缺少密码强度验证
```

### 安全风险
- **风险等级**: 🔴 高
- **影响**: 攻击者可轻易破解弱密码账户
- **CVE参考**: CWE-521 (Weak Password Requirements)

### 解决方案
在注册和密码修改时添加密码强度验证：

```python
import re

def validate_password_strength(password):
    """
    验证密码强度
    要求：
    - 至少8个字符
    - 包含大写字母
    - 包含小写字母
    - 包含数字
    - 包含特殊字符
    """
    if len(password) < 8:
        return False, '密码长度不能少于8位'
    
    if not re.search(r'[A-Z]', password):
        return False, '密码必须包含至少一个大写字母'
    
    if not re.search(r'[a-z]', password):
        return False, '密码必须包含至少一个小写字母'
    
    if not re.search(r'\d', password):
        return False, '密码必须包含至少一个数字'
    
    if not re.search(r'[!@#$%^&*(),.?":{}|<>]', password):
        return False, '密码必须包含至少一个特殊字符'
    
    # 检查常见弱密码
    weak_passwords = ['password', '123456', 'qwerty', 'admin', 'letmein']
    if password.lower() in weak_passwords:
        return False, '密码过于简单，请使用更强的密码'
    
    return True, ''

# 在 register_view 中使用
is_valid, error_msg = validate_password_strength(password)
if not is_valid:
    return JsonResponse({'code': 400, 'message': error_msg})
```

### 修改文件
1. `apps/users/views.py` - register_view() 函数
2. `apps/users/views.py` - change_password_view() 函数
3. `apps/users/views.py` - reset_password_view() 函数

## 问题2: 无效Token被接受

### 问题描述
测试显示使用无效Token（如 `invalid_token`, 空字符串）访问API时返回200成功，而不是401未授权。

### 问题位置
- 文件: `apps/users/views.py`
- 函数: `jwt_required()` 装饰器 (第82-116行)

### 问题原因分析
1. 部分API端点没有使用 `@jwt_required` 装饰器
2. 或者装饰器的Token验证逻辑存在问题

### 安全风险
- **风险等级**: 🔴 高
- **影响**: 攻击者可绕过认证访问受保护资源
- **CVE参考**: CWE-287 (Improper Authentication)

### 解决方案

#### 方案1: 统一使用DRF认证类
推荐使用Django REST Framework的认证类，而不是自定义装饰器：

```python
# settings.py
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'apps.users.authentication.JWTAuthentication',
    ],
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticated',
    ],
}
```

#### 方案2: 修复装饰器
确保所有需要认证的视图都使用了 `@jwt_required` 装饰器：

```python
@csrf_exempt
@jwt_required  # 确保添加此装饰器
def profile_view(request):
    # ...
```

### 修改文件
1. `apps/users/views.py` - 确保所有敏感API都使用认证装饰器
2. `apps/projects/views.py` - 同上
3. `apps/testcase/views.py` - 同上

## 问题3: 未授权访问被允许

### 问题描述
测试显示未登录用户可以访问某些需要认证的API端点。

### 问题位置
- 文件: `apps/projects/views.py`
- 文件: `apps/testcase/views.py`

### 问题原因
API视图没有正确配置认证和权限控制。

### 安全风险
- **风险等级**: 🔴 高
- **影响**: 敏感数据泄露，未授权操作

### 解决方案

#### 为所有API添加认证
```python
from rest_framework.decorators import authentication_classes, permission_classes
from rest_framework.permissions import IsAuthenticated
from apps.users.authentication import JWTAuthentication

@authentication_classes([JWTAuthentication])
@permission_classes([IsAuthenticated])
def some_api_view(request):
    # ...
```

#### 或在settings.py中全局配置
```python
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'apps.users.authentication.JWTAuthentication',
    ],
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticated',
    ],
}
```

## 问题4: SQL注入风险

### 问题描述
测试显示SQL注入payload在登录接口返回200，可能存在SQL注入风险。

### 问题位置
- 文件: `apps/users/views.py`
- 函数: `login_view()` (第160-233行)

### 问题原因分析
虽然Django的ORM和 `authenticate()` 函数已经做了参数化查询防护，但返回200可能是因为：
1. SQL注入字符串被当作普通用户名处理
2. 系统没有正确区分"用户不存在"和"密码错误"

### 安全风险
- **风险等级**: 🟡 中（Django ORM已有基础防护）
- **影响**: 可能的信息泄露

### 解决方案

#### 1. 统一错误消息
```python
# 不要区分用户名不存在和密码错误
if not user:
    return JsonResponse({'code': 401, 'message': '用户名或密码错误'})
```

#### 2. 添加输入验证
```python
import re

def sanitize_input(input_string):
    """清理输入，移除潜在危险字符"""
    # 只允许字母、数字、下划线、中文
    if not re.match(r'^[\w\u4e00-\u9fff@.+-]+$', input_string):
        return None
    return input_string

# 在登录时验证
username = sanitize_input(data.get('username', ''))
if username is None:
    return JsonResponse({'code': 400, 'message': '用户名格式不正确'})
```

#### 3. 添加登录日志
```python
# 记录登录尝试
import logging
logger = logging.getLogger('security')

logger.warning(f'登录尝试失败: username={username}, ip={request.META.get("REMOTE_ADDR")}')
```

## 问题5: DEBUG模式开启

### 问题描述
生产环境中DEBUG模式开启，会泄露敏感的系统信息。

### 问题位置
- 文件: `Testbackend/settings.py`
- 第27行

### 问题代码
```python
DEBUG = os.environ.get('DJANGO_DEBUG', 'True').lower() in ('true', '1', 'yes')
```

### 安全风险
- **风险等级**: 🟡 中
- **影响**: 泄露服务器配置、代码路径、敏感变量
- **CVE参考**: CWE-209 (Information Exposure Through Error Message)

### 解决方案

#### 1. 生产环境关闭DEBUG
```python
# 生产环境设置
DEBUG = False

# 或通过环境变量控制
DEBUG = os.environ.get('DJANGO_DEBUG', 'False').lower() == 'true'
```

#### 2. 配置ALLOWED_HOSTS
```python
ALLOWED_HOSTS = ['your-domain.com', 'www.your-domain.com']
```

#### 3. 自定义错误页面
```python
# urls.py
handler404 = 'apps.core.views.custom_404'
handler500 = 'apps.core.views.custom_500'
```

## 附录：安全最佳实践

### 1. 密码安全
- 使用强密码策略
- 使用bcrypt或Argon2加密存储
- 实施密码过期策略

### 2. 认证安全
- 使用HTTPS传输
- JWT Token设置合理过期时间
- 实施Token刷新机制

### 3. 访问控制
- 最小权限原则
- 基于角色的访问控制(RBAC)
- 定期审计权限

### 4. 输入验证
- 所有用户输入必须验证
- 使用参数化查询
- 输出编码防止XSS

### 5. 安全配置
- 关闭DEBUG模式
- 设置安全响应头
- 定期更新依赖包
