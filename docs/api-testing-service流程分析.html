AI驱动接口自动化流程分析

api-testing-service 微服务架构详解

一、整体架构

基于 FastAPI + WeKnora知识库 + SSE流式传输 构建的5阶段流水线式AI驱动API测试系统

核心数据流：知识库接口文档 → AI生成用例 → AI分析依赖 → AI预填充 → 执行测试 → AI校验结果

技术栈：FastAPI（异步框架） + httpx（HTTP客户端） + WeKnora（RAG知识库） + SSE（流式传输）

五、自愈能力详解

1. 参数自愈

检测到request_body缺失 → 自动调用AI预填充 → 继续执行

# 检测到request_body缺失 → 自动调用AI预填充 if needs_prefill: prefilled_run_list = await self._prefill_all_params(...)

2. 变量自愈

支持多种占位符格式（{{var}}、${{var}}、{var}），自动从runtime_vars替换

# 支持多种占位符格式，自动从runtime_vars替换 for fmt in ["${{var}}", "{{var}}", "{var}"]: if fmt in s: s = s.replace(fmt, str(value))

3. 认证自愈

自动从前置接口提取Token和Cookie，注入后续接口的headers

# 自动注入Token和Cookie if "token" in var_name.lower(): headers["Authorization"] = f"Bearer {token_value}" if "sessionid" in var_name.lower(): headers["Cookie"] = f"sessionid={value}"

4. 状态码自愈

错误场景同类匹配：预期401，实际403也算通过（都是4XX，系统正确拒绝了请求）

# 错误场景同类匹配：预期401，实际403也算通过 if 400 <= expected < 600: return (expected // 100) == (actual // 100)

5. 账号自愈

时间戳格式用户名 + 映射表保证注册登录一致性 + 执行完自动清理

# 时间戳格式用户名 + 映射表 pattern = r'^test_\d{8}_\d{6}_[a-z0-9]{4}$' # 注册时生成 → 映射表记录 → 登录时匹配 → 执行完清理

六、设计决策、亮点与待优化点

优秀设计亮点

  • 采用RAG知识库绑定接口文档，AI输出严格基于真实业务，有效规避大模型幻觉
  • 运行时动态参数注入，解决复杂接口链路数据依赖痛点
  • 自动认证注入，Token和Cookie自动从前置接口提取并注入后续接口
  • 分层状态码匹配，正常场景精确匹配，错误场景同类匹配，避免误判
  • 测试账号自动管理，时间戳+映射表保证注册登录一致性，执行完自动清理
  • 全流程提示词模板化，解耦易维护、便于迭代调优
  • 会话隔离、JSON容错、SSE流式输出，兼顾稳定性与前端交互体验

现存待优化点

  • 长接口链路下，频繁创建/销毁知识库会话，存在性能损耗
  • LLM输出格式不稳定，依赖大量容错逻辑，仍存在解析风险
  • 缺少会话复用、结果缓存机制，长任务执行效率可进一步提升
  • 并发执行能力有限，无依赖的接口可并发执行提升效率
  • 断言依赖AI，规则断言覆盖不足，可增加更多内置规则断言

七、面试话术（完整版）

1. 项目介绍（开场白）

"我独立开发了一个AI驱动的接口自动化测试系统，采用微服务架构，包含5个核心阶段：

用例生成 → 依赖分析 → 数据填充 → 执行测试 → 结果校验

技术栈是FastAPI + WeKnora知识库 + SSE流式传输，实现了从接口文档到测试报告的全流程自动化，测试效率提升10倍以上。"

2. 技术选型原因

为什么用FastAPI？

  • 原生支持异步，适合AI调用这种IO密集型场景
  • 自动生成API文档（Swagger），前后端对接方便
  • SSE流式输出支持好，我们的AI生成需要实时推送
  • 性能接近Go/Node.js，比Django异步更高效

为什么用WeKnora知识库？

  • 提供RAG检索增强，AI生成用例时能引用真实接口文档
  • 避免大模型幻觉，保证生成的用例真实可用
  • 支持流式问答，前端实时展示AI思考过程

3. 核心功能详解

阶段1 - 用例生成：

用户上传接口文档到知识库，AI结合RAG检索生成测试用例，覆盖边界值、等价类、安全测试等场景。

阶段2 - 依赖分析：

AI自动分析接口依赖关系，输出执行顺序和变量提取规则。比如"注册→登录→修改信息"，AI会标注从登录响应提取token。

阶段3 - 数据填充：

AI填充静态参数（用户名、密码等），保留动态占位符（{{token}}、{{user_id}}）给运行时替换。

阶段4 - 执行测试：

按序执行接口，动态提取上游响应填充下游参数，自动注入Token和Cookie，实时推送执行进度。

阶段5 - 结果校验：

AI综合判断测试结果，关注状态码、业务code、跨接口数据一致性，错误场景同类匹配（预期401实际403也算通过）。

4. 技术亮点

1. RAG知识库绑定接口文档

AI生成用例时引用真实接口文档，避免幻觉，保证用例真实可用。

2. 运行时动态参数注入

执行阶段动态提取上游响应，自动填充下游接口参数，解决复杂接口链路数据依赖痛点。

3. 多层自愈能力

  • 参数缺失 → AI自动预填充
  • 占位符 → 运行时自动替换
  • 认证信息 → 自动注入Token和Cookie
  • 状态码 → 智能匹配（错误场景同类匹配）
  • 测试账号 → 时间戳+映射表+自动清理

4. 分层状态码匹配

正常场景精确匹配（预期200必须200），错误场景同类匹配（预期401，实际403也算通过），避免误判。

5. SSE流式传输

AI生成和执行过程实时推送，前端实时展示进度，用户体验好，避免HTTP超时。

5. 遇到的难点与解决方案

难点1：LLM输出格式不稳定

AI有时返回Markdown包裹、多余说明文字，导致JSON解析失败。

解决方案：多层容错机制

  • 清理thinking标签
  • 定位JSON起始位置
  • 提取代码块
  • 正则匹配JSON结构
  • 3次重试 + 递减温度（1.0→0.9→0.7）

结果：解析成功率从60%提升到95%以上

难点2：接口依赖数据传递

登录接口返回token，后续接口需要使用，传统方案硬编码或脚本提取。

解决方案：运行时动态变量提取

  • 依赖分析阶段声明extract_vars（如 {"token": "$.run_list[1].response.body.data.token"}）
  • 执行阶段从响应中提取变量存入runtime_vars
  • 后续接口自动替换{{token}}占位符
  • 自动注入Token到Authorization、Cookie到headers

难点3：测试账号管理

注册和登录需要使用同一个账号，并发执行时账号冲突。

解决方案：时间戳+映射表机制

  • 注册时生成时间戳格式用户名：test_20260617_143000_a1b2
  • 映射表记录"原始用户名→实际用户名"
  • 登录时从映射表查找对应账号
  • 执行完成后自动清理测试账号
