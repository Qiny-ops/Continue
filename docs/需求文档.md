## 一、项目概述

### 1.1 项目背景

#### 1.1.1 行业背景

随着软件行业的快速发展，软件质量保障变得越来越重要。根据行业调研数据：

- 软件缺陷修复成本随开发阶段推进呈指数级增长
- 测试用例是软件测试的核心资产，其管理效率直接影响测试质量
- 70%以上的测试团队仍在使用 Excel、Word 等传统工具管理测试用例

#### 1.1.2 现状问题

传统测试用例管理方式存在以下痛点：

| 问题类别 | 具体表现 | 影响程度 |
|----------|----------|----------|
| **协作困难** | 多人同时编辑导致版本冲突、内容覆盖；无法实时看到他人修改 | 高 |
| **版本管理混乱** | 难以追踪用例的变更历史；无法回滚到历史版本；不知道谁在何时修改了什么 | 高 |
| **复用性差** | 不同项目间用例难以复用；每次新项目都要重新编写类似用例 | 中 |
| **统计困难** | 难以快速获取测试覆盖率、执行情况等统计数据；报表制作耗时 | 高 |
| **关联性弱** | 用例与需求、缺陷的关联关系难以维护；无法追溯用例覆盖了哪些需求 | 中 |
| **检索效率低** | 无法快速定位特定用例；缺乏有效的搜索和筛选机制 | 中 |
| **流程不规范** | 用例评审流程缺失；执行记录不完整；缺乏质量把控机制 | 高 |

#### 1.1.3 解决方案

开发一套专业的测试用例管理系统，提供：

- 统一的用例管理平台
- 规范的用例编写模板
- 完善的版本控制机制
- 高效的协作编辑能力
- 灵活的权限管理体系
- 丰富的统计分析报表

### 1.2 项目目标

#### 1.2.1 总体目标

构建一个功能完善、易于使用、安全可靠的测试用例管理系统，提升测试团队的工作效率和测试质量。

#### 1.2.2 具体目标

| 目标 | 描述 | 衡量指标 |
|------|------|----------|
| **集中管理** | 提供统一的测试用例管理平台 | 所有测试用例100%纳入系统管理 |
| **高效协作** | 支持多人协作编辑，实时同步 | 协作效率提升50%以上 |
| **版本控制** | 支持用例版本管理，可追溯变更 | 变更历史100%可追溯 |
| **结构化组织** | 支持树形目录结构组织用例 | 用例检索时间减少60% |
| **统计分析** | 提供多维度的统计数据和可视化报表 | 报表生成时间减少80% |
| **流程管理** | 支持用例评审、执行等完整流程 | 用例质量提升30% |

## 三、功能需求详细说明

### 3.1 用户管理模块

#### 3.1.1 功能概述

用户管理模块负责用户的全生命周期管理，包括注册、登录、信息管理和权限控制。

#### 3.1.2 用户注册

**功能描述**：新用户通过注册页面创建账户。

**前置条件**：
- 用户未登录系统
- 用户拥有有效的邮箱地址

**输入项**：

| 字段名 | 类型 | 必填 | 长度限制 | 格式要求 | 说明 |
|--------|------|------|----------|----------|------|
| username | string | 是 | 4-50字符 | 字母开头，仅含字母数字下划线 | 用户名，全局唯一 |
| password | string | 是 | 8-128字符 | 至少包含大小写字母和数字 | 登录密码 |
| confirmPassword | string | 是 | 8-128字符 | 与password一致 | 确认密码 |
| email | string | 是 | 5-254字符 | 有效邮箱格式 | 邮箱地址，全局唯一 |
| name | string | 是 | 2-100字符 | 中英文、数字 | 用户真实姓名 |
| phone | string | 否 | 11字符 | 手机号格式 | 手机号码 |

**处理流程**：

```
开始
  ↓
用户填写注册表单
  ↓
前端校验格式 ──[校验失败]──→ 提示错误信息
  ↓ [校验通过]
提交注册请求
  ↓
后端校验 ──[校验失败]──→ 返回错误信息
  ↓ [校验通过]
检查用户名是否存在 ──[存在]──→ 返回"用户名已存在"
  ↓ [不存在]
检查邮箱是否已注册 ──[已注册]──→ 返回"邮箱已被注册"
  ↓ [未注册]
密码加密存储
  ↓
创建用户记录（状态：active）
  ↓
分配默认角色（guest）
  ↓
返回成功信息
  ↓
结束
```

**业务规则**：
1. 用户名必须全局唯一，不区分大小写
2. 邮箱必须全局唯一，不区分大小写
3. 密码必须加密存储（使用 Django 的 PBKDF2 算法）
4. 新注册用户默认分配 guest 角色
5. 新注册用户默认状态为 active

**异常处理**：

| 异常情况 | 错误码 | 错误信息 | 处理方式 |
|----------|--------|----------|----------|
| 用户名已存在 | 400 | 用户名已存在 | 提示用户更换用户名 |
| 邮箱已注册 | 400 | 邮箱已被注册 | 提示用户直接登录或找回密码 |
| 密码强度不足 | 400 | 密码强度不足，请包含大小写字母和数字 | 提示用户修改密码 |
| 网络错误 | - | 网络连接失败，请稍后重试 | 提示用户检查网络 |

**输出项**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| code | int | 状态码，200表示成功 |
| message | string | 提示信息 |
| data | object | 用户基本信息 |

#### 3.1.3 用户登录

**功能描述**：已注册用户通过登录页面进入系统。

**前置条件**：
- 用户已注册
- 用户账户状态为 active

**输入项**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | string | 是 | 用户名或邮箱 |
| password | string | 是 | 登录密码 |

**处理流程**：

```
开始
  ↓
用户输入用户名和密码
  ↓
前端校验非空 ──[校验失败]──→ 提示错误
  ↓ [校验通过]
提交登录请求
  ↓
验证用户凭证
  ↓
检查用户是否存在 ──[不存在]──→ 返回"用户名或密码错误"
  ↓ [存在]
检查密码是否正确 ──[不正确]──→ 返回"用户名或密码错误"
  ↓ [正确]
检查用户状态 ──[非active]──→ 返回"账号已被禁用"
  ↓ [active]
生成 JWT Token
  ↓
更新最后登录时间和IP
  ↓
返回用户信息和Token
  ↓
前端存储Token
  ↓
跳转到首页
  ↓
结束
```

**业务规则**：
1. 支持用户名或邮箱登录
2. 密码错误不提示具体是用户名错误还是密码错误（安全考虑）
3. 连续登录失败5次，锁定账户30分钟（可选功能）
4. Token 有效期24小时
5. 记录登录时间和IP地址

**输出项**：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": 1,
    "username": "admin",
    "name": "管理员",
    "email": "admin@example.com",
    "phone": "13800138000",
    "system_role": "超级管理员",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

#### 3.1.4 密码找回

**功能描述**：用户忘记密码时，通过邮箱重置密码。

**前置条件**：
- 用户已注册
- 用户邮箱有效可用

**处理流程**：

```
开始
  ↓
用户点击"忘记密码"
  ↓
输入注册邮箱
  ↓
验证邮箱格式 ──[格式错误]──→ 提示错误
  ↓ [格式正确]
检查邮箱是否已注册 ──[未注册]──→ 返回"邮箱未注册"
  ↓ [已注册]
生成重置令牌（32位随机字符串）
  ↓
设置令牌过期时间（24小时）
  ↓
保存令牌到用户记录
  ↓
发送重置邮件
  ↓
返回成功信息
  ↓
结束
```

**邮件内容模板**：

```
主题：【测试用例管理系统】重置密码

尊敬的用户：

您好！您正在申请重置密码，请点击以下链接完成操作：

http://yourdomain.com/reset-password/{token}

此链接将在24小时后失效，请尽快完成操作。

如果您没有申请重置密码，请忽略此邮件。

测试用例管理系统
```

#### 3.1.5 密码重置

**功能描述**：用户通过重置链接设置新密码。

**输入项**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| token | string | 是 | URL路径参数，重置令牌 |
| new_password | string | 是 | 新密码 |
| confirm_password | string | 是 | 确认新密码 |

**处理流程**：

```
开始
  ↓
用户点击邮件中的重置链接
  ↓
验证令牌有效性
  ↓

  ↓

  ↓
```

| CSRF防护 | 防止跨站请求伪造 | CSRF Token |
| SQL注入防护 | 防止SQL注入攻击 | ORM参数化查询 |
